= Apache TomEE Security Vulnerabilities
:jbake-type: page
:jbake-status: published

This page lists the security vulnerabilities fixed in Apache TomEE releases.
Each vulnerability is given a security impact rating by either the Apache TomEE team or by the dependent project supplying the fix - please note that this rating is not uniform and will vary from project to project.
We also list the versions of Apache TomEE the flaw is known to affect, and where a flaw has not been verified list the version with a question mark.

NOTE: Vulnerabilities that are not TomEE vulnerabilities but have either been incorrectly reported against TomEE or where TomEE provides a workaround are listed bellow in the section "Not a vulnerability".

Please note that binary patches are never provided.
If you need to apply a source code patch, use the building instructions for the Apache TomEE version that you are using.
Instructions for building TomEE from source are available xref:../community/sources.adoc[here].

If you need help on building or configuring TomEE or other help on following the instructions to mitigate the known vulnerabilities listed here, please send your questions to the public xref:../support.adoc[Users mailing list]

If you have encountered an unlisted security vulnerability or other unexpected behaviour that has security impact, or if the descriptions here are incomplete, please report them privately to the https://www.apache.org/security[Apache Security Team].
Thank you.

== Fixed in Apache TomEE 10.3.0 and 11.0.0-M2

The following vulnerabilities were announced on 10 November 2026. All of them are resolved in
link:../10.3.0/release-notes.html[Apache TomEE 10.3.0] and link:../11.0.0-M2/release-notes.html[Apache TomEE 11.0.0-M2].
Several fixes change default behavior. See the link:../10.3.0/migration-guide.html[TomEE 10.3.0 migration guide] and the
link:../11.0.0-M2/migration-guide.html[TomEE 11.0.0-M2 migration guide] before upgrading.

=== Vulnerabilities in removed modules

The following vulnerabilities affect optional modules that are no longer part of TomEE 10.3.0 and 11.0.0-M2:
the embedded OpenEJB HTTP server (`openejb-http`) and the endpoints it published, the Hessian remoting module
(`openejb-hessian`), and the SSH administration shell (`openejb-ssh`, `openejb-common-cli`). No fixed version of these
modules exists. Upgrading to TomEE 10.3.0 or 11.0.0-M2 removes them. If you cannot upgrade, block network access to these
services from untrusted clients or stop using them.

=== Details

[[CVE-2026-86336]]
==== Important: EJB method authorization is silently skipped on JDK 21+

link:https://www.cve.org/CVERecord?id=CVE-2026-86336[CVE-2026-86336] -
link:https://lists.apache.org/thread/tv0407xmnpy4qctqm9nzx56lgjln2t4j[Announcement]

Apache TomEE running on JDK 21 or later skips EJB method authorization checks, allowing callers to invoke EJB methods without the configured access restrictions being enforced.

Affected versions:

* `org.apache.tomee:openejb-core` 10.1.1 before 10.3.0
* `org.apache.tomee:openejb-core` 11.0.0-M1 before 11.0.0-M2

Credit: The Apache Software Foundation (finder), Claude Security (tool), Markus Jung (remediation developer)

[[CVE-2026-111244]]
==== Important: Authorization bypass in MicroProfile JWT role checks for JAX-RS resources

link:https://www.cve.org/CVERecord?id=CVE-2026-111244[CVE-2026-111244] -
link:https://lists.apache.org/thread/flpx4mgmzqx36fm6gy3thcoh74b5yz7o[Announcement]

When MicroProfile JWT role-based access control is used, the access constraints of JAX-RS resources are not always enforced as declared: resources that declare an empty set of allowed roles are accessible to every caller, resource classes that inherit the same method from a common superclass share their constraints, and class-level constraints declared on a superclass are ignored. A remote attacker can invoke resources that should be denied to them, in some configurations without authentication.

Affected versions:

* `org.apache.tomee:mp-jwt` 7.1.0 before 10.0.0-M1
* `org.apache.tomee:mp-jwt` 10.0.0-M1 before 10.3.0
* `org.apache.tomee:mp-jwt` 11.0.0-M1 before 11.0.0-M2

Credit: The Apache Software Foundation (finder), Claude Security (tool), Richard Zowalla (remediation developer)

[[CVE-2026-111257]]
==== Important: Well-known administrative credentials created at startup

link:https://www.cve.org/CVERecord?id=CVE-2026-111257[CVE-2026-111257] -
link:https://lists.apache.org/thread/gzzn7jbzrfk8bo9ttmqhr3c6q3szc5vf[Announcement]

With the default configuration and no users defined in the default user database, TomEE silently adds an administrative user with a well-known password at startup. A remote attacker can use these credentials to authenticate to web applications that use the default realm and grant access to any authenticated user or to the TomEE administrative role.

Affected versions:

* `org.apache.openejb:tomee-catalina` 1.5.1 through 1.7.5
* `org.apache.tomee:tomee-catalina` 7.0.0-M1 before 10.0.0-M1
* `org.apache.tomee:tomee-catalina` 10.0.0-M1 before 10.3.0
* `org.apache.tomee:tomee-catalina` 11.0.0-M1 before 11.0.0-M2

Credit: The Apache Software Foundation (finder), Claude Security (tool), Markus Jung (remediation developer)

[[CVE-2026-111241]]
==== Moderate: Local code execution via predictable passivation files in the shared temporary directory

link:https://www.cve.org/CVERecord?id=CVE-2026-111241[CVE-2026-111241] -
link:https://lists.apache.org/thread/kbpc7t241483pnxo2sccrhyp6pjkwbq2[Announcement]

When a non-default stateful session bean passivation strategy is configured, passivated bean state is written to predictably named files in the shared system temporary directory, reusing files that already exist there, and is deserialized on activation. Affected versions:
